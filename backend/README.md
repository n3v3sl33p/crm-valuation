# CRM Система Оценки Недвижимости (Backend)

Backend-сервис для агентства оценки недвижимости, реализованный на FastAPI. Предоставляет API для полного цикла обработки заявок на оценку: от создания заявки клиентом до финального утверждения отчета.

## Технологический стек

*   **Язык**: Python 3.13+
*   **Фреймворк**: FastAPI
*   **База данных**: SQLite (с использованием `aiosqlite` для асинхронности)
*   **ORM**: SQLAlchemy (Async)
*   **Аутентификация**: JWT (JSON Web Tokens), bcrypt
*   **Валидация**: Pydantic v2
*   **Контейнеризация**: Docker

## Структура проекта

*   `app/api/v1` - Эндпоинты API (авторизация, пользователи, заявки).
*   `app/core` - Конфигурация, подключение к БД, безопасность.
*   `app/models` - Модели базы данных (SQLAlchemy).
*   `app/schemas` - Pydantic схемы для валидации данных.

## Ролевая модель

1.  **CLIENT (Клиент)**: Создает заявки, следит за статусом, принимает финальный отчет.
2.  **EMPLOYEE (Сотрудник)**: Менеджер. Согласовывает заявки, назначает оценщиков, проверяет отчеты перед отправкой клиенту.
3.  **APPRAISER (Оценщик)**: Получает назначенные заявки, проводит осмотр, загружает отчет (в виде текста/ссылки).

## Тестовые пользователи (Создаются автоматически)

При запуске приложения в базе данных автоматически создаются следующие пользователи (пароль для всех: `String1`):

1.  **Клиент**: `user@mail.com` (Role: CLIENT)
2.  **Сотрудник**: `admin@mail.com` (Role: EMPLOYEE)
3.  **Оценщик**: `appraiser@mail.com` (Role: APPRAISER)

## Запуск проекта

**ВАЖНО:** Если вы обновляете код и меняете схему БД (добавляете новые поля), **удалите старый файл `backend/data/valuation.db` (или `valuation.db`)**, чтобы база данных пересоздалась с новой структурой.

### Вариант 1: Docker (Рекомендуемый)

1.  **Создайте файл `.env` в папке `backend`:**
    ```env
    SECRET_KEY=ваш_надежный_ключ_минимум_32_символа
    ALGORITHM=HS256
    DATABASE_URL=sqlite+aiosqlite:///./data/valuation.db
    ```

2.  **Сборка образа:**
    В папке `backend` выполните команду:
    ```bash
    docker build -t valuation-backend .
    ```

3.  **Запуск контейнера:**
    Запустите контейнер, пробросив файл `.env` и смонтировав файл базы данных:
    ```bash
    # Linux / MacOS
    docker run -d -p 8000:8000 \
      --env-file .env \
      -v $(pwd)/data:/app/data \
      valuation-backend
    
    # Windows (PowerShell)
    docker run -d -p 8000:8000 `
      --env-file .env `
      -v ${PWD}/data:/app/data `
      valuation-backend
    ```
    
    **Или используйте Docker Compose** (рекомендуется):
    ```bash
    docker-compose up -d --build
    ```

4.  **Доступ:**
    Сервис будет доступен по адресу: `http://localhost:8000`.
    Автоматическая документация (Swagger UI): `http://localhost:8000/docs`.
    
    **Примечание:** База данных `valuation.db` сохраняется между перезапусками контейнера благодаря volume. Файл базы данных находится в папке `backend/` на хосте.

### Вариант 2: Локальный запуск (Без Docker)

1.  Установите зависимости с помощью `uv`:
    ```bash
    cd backend
    pip install uv
    uv sync
    ```

2.  Создайте файл `.env` в папке `backend`:
    ```env
    SECRET_KEY=ваш_надежный_ключ_минимум_32_символа
    ALGORITHM=HS256
    DATABASE_URL=sqlite+aiosqlite:///./valuation.db
    ```

3.  Запустите сервер:
    ```bash
    uv run uvicorn app.main:app --reload
    ```


## Сценарий работы (Workflow)

Ниже описан "счастливый путь" обработки заявки через API (Swagger UI).

### Шаг 0: Авторизация
Используйте эндпоинт `POST /api/v1/auth/login`. Полученный `access_token` нужно вставить в кнопку **Authorize** вверху Swagger UI (формат: `Bearer <token>`, но Swagger часто подставляет префикс сам, вводите просто токен или как просит UI).

### Шаг 1: Клиент создает заявку (Черновик)
*   **Кто:** `user@mail.com` (CLIENT)
*   **Метод:** `POST /api/v1/valuations/`
*   **Тело запроса:**
    Теперь необходимо указывать структурированный адрес и тип недвижимости.
    
    *Пример для Квартиры:*
    ```json
    {
      "city": "Москва",
      "street": "Улица Пушкина",
      "house_number": "10",
      "property_type": "APARTMENT",
      "apartment_number": "45", 
      "floor": 5,
      "description": "Черновая отделка, окна во двор"
    }
    ```
    
    *Пример для Офиса:*
    ```json
    {
      "city": "Санкт-Петербург",
      "street": "Невский проспект",
      "house_number": "20",
      "property_type": "OFFICE",
      "office_number": "301",
      "floor": 3,
      "description": "Офис класса А, требуется пропуск"
    }
    ```
*   **Результат:** Заявка создана, статус `DRAFT`. Сотрудник её пока **не видит**.

### Шаг 1.1: Клиент редактирует и отправляет заявку
Клиент проверяет данные, при необходимости меняет их (через PATCH). Затем отправляет сотруднику.
*   **Кто:** `user@mail.com` (CLIENT)
*   **Метод:** `PATCH /api/v1/valuations/{id}`
*   **Тело запроса:**
    ```json
    {
      "status": "CREATED",
      "comment_text": "Отправляю на согласование."
    }
    ```
*   **Результат:** Статус `CREATED`. Теперь заявка видна сотруднику.

### Шаг 2: Сотрудник проверяет (и может вернуть)

#### Вариант А: Возврат на доработку
*   **Кто:** `admin@mail.com` (EMPLOYEE)
*   **Метод:** `PATCH /api/v1/valuations/{id}`
*   **Тело запроса:**
    ```json
    {
      "status": "RETURNED_TO_CLIENT",
      "comment_text": "Уточните номер квартиры в адресе."
    }
    ```
*   **Результат:** Статус `RETURNED_TO_CLIENT`. Клиент исправляет данные (PATCH полей) и снова переводит в `CREATED` (см. Шаг 1.1).

#### Вариант Б: Согласование
*   **Кто:** `admin@mail.com` (EMPLOYEE)
*   **Метод:** `PATCH /api/v1/valuations/{id}`
*   **Тело запроса:**
    ```json
    {
      "status": "APPROVED_BY_EMPLOYEE",
      "comment_text": "Заявка принята. Ищем оценщика."
    }
    ```

### Шаг 3: Сотрудник назначает Оценщика
*   **Кто:** `admin@mail.com` (EMPLOYEE)
*   **Действие:** Назначает оценщика (например, ID=3 для `appraiser@mail.com`) и **обязательно** указывает дату оценки.
*   **Метод:** `PATCH /api/v1/valuations/{id}`
*   **Тело запроса:**
    ```json
    {
      "appraiser_id": 3,
      "assessment_date": "2023-12-25T14:00:00",
      "comment_text": "Назначен оценщик appraiser на 25 декабря."
    }
    ```
*   **Результат:** Статус автоматически меняется на `APPRAISER_ASSIGNED`.

### Шаг 4: Оценщик сдает отчет (Или отказывается)

#### Вариант А: Успешная сдача отчета
Оценщик теперь обязан заполнить ссылку на отчет и критерии оценки (1-10).
*   **Кто:** `appraiser@mail.com` (APPRAISER)
*   **Метод:** `PATCH /api/v1/valuations/{id}`
*   **Тело запроса:**
    ```json
    {
      "status": "REPORT_SUBMITTED",
      "comment_text": "Оценка завершена. Рыночная стоимость: 12 млн. руб.",
      "report_url": "https://disk.yandex.ru/i/example_report.pdf",
      "final_price": 12000000.00,
      "condition_score": 8,
      "location_score": 9,
      "liquidity_score": 7,
      "material_quality_score": 8,
      "legal_purity_score": 10
    }
    ```
*   **Важно:** Текст комментария на этом этапе считается сводкой отчета.

#### Вариант Б: Оценщик отказывается от заявки (Самоотмена)
Если оценщик не может выполнить работу, он возвращает заявку сотруднику.
*   **Кто:** `appraiser@mail.com` (APPRAISER)
*   **Метод:** `PATCH /api/v1/valuations/{id}`
*   **Тело запроса:**
    ```json
    {
      "status": "APPROVED_BY_EMPLOYEE",
      "comment_text": "Не могу выехать на объект в назначенное время."
    }
    ```
*   **Результат:** Статус возвращается на `APPROVED_BY_EMPLOYEE`, назначение оценщика и дата оценки сбрасываются. Заявка снова видна сотруднику для переназначения.

### Шаг 5: Сотрудник проверяет отчет (и может вернуть)

#### Вариант А: Возврат Оценщику
*   **Кто:** `admin@mail.com` (EMPLOYEE)
*   **Метод:** `PATCH /api/v1/valuations/{id}`
*   **Тело запроса:**
    ```json
    {
      "status": "RETURNED_TO_APPRAISER",
      "comment_text": "Отчет неполный, добавьте фото кухни."
    }
    ```
*   **Результат:** Статус `RETURNED_TO_APPRAISER`. Оценщик дорабатывает и снова сдает (см. Шаг 4 Вариант А).

#### Вариант Б: Утверждение отчета
*   **Кто:** `admin@mail.com` (EMPLOYEE)
*   **Метод:** `PATCH /api/v1/valuations/{id}`
*   **Тело запроса:**
    ```json
    {
      "status": "REPORT_APPROVED_BY_EMPLOYEE",
      "comment_text": "Отчет проверен, отправлен клиенту."
    }
    ```

### Шаг 6: Клиент принимает работу
*   **Кто:** `user@mail.com` (CLIENT)
*   **Метод:** `PATCH /api/v1/valuations/{id}`
*   **Тело запроса:**
    ```json
    {
      "status": "COMPLETED",
      "comment_text": "Спасибо, работа принята."
    }
    ```
